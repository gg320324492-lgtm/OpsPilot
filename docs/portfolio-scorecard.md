## 3. 「30 秒理解 / 3 分钟演示」测试方法

来源：phase3-plan §1 的信息设计目标与 §6 M3-06 验收要求。
目的：用真实读者检验首屏理解与短时演示是否达标，记录误解并修正材料。

### 3.1 测试流程

1. **招募读者**：至少 1 位非作者读者（理想 2–3 位：1 位技术背景、1 位业务/采购背景）。
   读者不应事先了解 OpsPilot。
2. **30 秒理解测试**：给读者看 README 首屏（或作品条目页），限时 30 秒，然后收起页面，
   请读者回答三个问题：
   - 这个项目解决什么问题？
   - 它是怎么工作的（一句话）？
   - 你会委托作者做什么类型的事？
   记录复述原文，不提示、不引导。
3. **3 分钟演示测试**：请读者自己（或观看作者操作）沿演示路径 A 走：
   提交工单 → 调查 → 政策引用 → 待审批 → 人工批准 → 模拟退款与审计。
   限时 3 分钟，观察并记录：卡住的位置、看不懂的界面文案、对"等待审批/已批准未执行/失败"的混淆。
4. **修正闭环**：每个误解点转化为一条修正项（改文案/改截图/改默认路径），修完后可复测。

### 3.2 记录模板

```markdown
## 30 秒 / 3 分钟测试记录

- 日期：YYYY-MM-DD
- 读者编号/背景：R1（技术 / 业务 / 混合）
- 测试材料版本：commit <sha>，README 首屏 / 演示路径 <A|B|C>

### 30 秒理解
| 问题 | 读者复述 | 是否命中预期 | 误解点 |
|---|---|---|---|
| 解决什么问题 | （原文记录） | 是/否 | （无 / 具体描述） |
| 怎么工作 | （原文记录） | 是/否 | |
```
