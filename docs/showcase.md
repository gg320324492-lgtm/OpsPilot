# Showcase — screenshots, cover and demo videos (Phase 3 M2-05)

Everything in this directory was recorded from the **real OpsPilot dashboard**
driving the **real two-process stack** (Next.js dashboard + FastAPI api +
worker + PostgreSQL/pgvector) that `scripts/demo_paths.py` brings up on the
disposable compose project `opspilot-demo-test`. Nothing is drawn by hand and
no placeholder stands in for a real frame.

## What is live and what is fake (read this first)

- **Live:** the dashboard UI, the API, the worker, the database, the approval
  gate, the idempotent refund execution, the audit trail. Every screenshot and
  every video frame is a real click or a real server state.
- **Scripted:** the *model*. `MODEL_PROVIDER=fake` replays the committed
  `duplicate_charge` / `already_refunded` fixtures
  (`evals/datasets/fixtures/`) — the same classification, the same tool
  proposals, every run. **No external AI service is called anywhere in this
  material.**
- **Disposable:** all data is committed seed data (`mcp_servers/*/seed.json`);
  the stack is torn down with `docker compose -p opspilot-demo-test down -v`,
  which cannot touch any other project's volumes.

This disclosure is printed on the cover image and on the title/end cards of
every video.

**Waiting-time handling.** The takes already carry presenter pacing (each beat
holds 6–14 s so a viewer can read the screen; the worker polls in real time
between states). The assembly adds only the title/end cards — no segment is
sped up and no state change is cut. Raw takes: `docs/assets/showcase-raw/videos/*.webm`.

## Reproduce

```bash
.venv/Scripts/python.exe scripts/demo_paths.py reset --api-port 18001 --web-port 3102 --pg-port 15434
cd web && node ../scripts/record_showcase.mjs --api 18001 --web 3102 --pg 15434
node ../scripts/export_screenshot.mjs --api 18001 --web 3102
node ../scripts/make_showcase_graphics.py
node ../scripts/cut_showcase_video.mjs
.venv/Scripts/python.exe ../scripts/make_showcase_subtitles.py   # from repo root
```

Record before every take: the fake provider replays its fixtures in order, one
full run per worker process — `reset` restores the cursor and the seed data.
