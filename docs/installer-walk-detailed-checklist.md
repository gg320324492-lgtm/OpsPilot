# OpsPilot v0.2.0 — 真人走查细化核对表（2026-11-16）

**配套于：** [`installer-interactive-walk-2026-11-15.md`](installer-interactive-walk-2026-11-15.md)
（主脚本，其表格是唯一的正式记录处）。本文件把主脚本第 0–5 部分的每一步展开成
**操作 → 预期断言 → 常见故障与处置 → 回填格式**，并补充主脚本未展开的细节
（版本号怎么看、容器名、健康检查、退出后状态核对）。

**使用方式：** 执行时把本文档当作"手边说明书"；**所有打勾与备注只写在主脚本的
表格里**，本文档不留记录。每一步标题后的 `[H]` 表示 headless 走查已验证过、
可简写快速通过；`[HUMAN]` 表示只有真人交互才能验证、需重点执行。

**结论速记：** 未签名 → SmartScreen 弹窗是正常的；首启动 5–15 分钟别中途退出；
8000/3000/5432 被占不影响本包（可跟随 `OPSPILOT_*_HOST_PORT` 环境变量换端口）；
退款只执行一次，重复批准返回 **HTTP 409**；退出时容器停、数据卷保留。

## 第 0 部分 — 开始前

### 0.1 [H] 确认 Docker Desktop 已安装并正在运行

- **操作：** 打开 Docker Desktop；确认托盘鲸鱼图标显示 running。再开一个
  PowerShell / CMD 窗口执行 `docker version`，应同时打印 Client 与 Server 版本号。
- **预期断言：** 托盘图标为 running；`docker version` 退出码 0，有 Server 段输出
  （如 `Server: Docker Desktop …`）。若只有 Client 段或报错 `error during connect`，
  说明 daemon 未就绪。
- **常见故障与处置：** ① Docker Desktop 装了但没启动 → 先启动它，等托盘变绿再继续；
  ② WSL2 报错（`WSL 2 installation is incomplete` 等）→ 按 Docker Desktop 提示
  更新 WSL 内核；③ 本机走了代理导致拉镜像失败 → 首次构建需要联网，参见已知限制。
- **回填格式：** 主脚本 0.1 行"实际记录"写 `Docker Desktop running；docker version OK（Client x.y / Server z.a）`。

### 0.2 [H] 核对安装包

- **操作：**
  1. 资源管理器里右键 `OpsPilot-Setup-0.2.0-x64.exe` → 属性 → **详细信息**，读"文件大小"与"产品版本"。
  2. 用 PowerShell 核对哈希：
     `Get-FileHash .\OpsPilot-Setup-0.2.0-x64.exe -Algorithm SHA256`
- **预期断言：** 大小 **130,075,633 字节**；产品版本 **0.2.0**；SHA-256
  `2461f146320f221f1a7570565c786b49e8c9a799a826d8ac4eea587726c19332`。三项全部一致才继续。
- **常见故障与处置：** 哈希不一致 → 文件在传输中被改坏或拿错版本，**停止走查**并联系项目所有者；
  属性页没有"产品版本" → 以 PowerShell 的 `(Get-Item .\OpsPilot-Setup-0.2.0-x64.exe).VersionInfo.ProductVersion` 输出为准。
- **回填格式：** 主脚本 0.2 行写 `大小一致 / 版本 0.2.0 / SHA-256 一致（或哈希不符：实测 ____）`。

### 0.3 [H] 记录 8000 / 3000 / 5432 端口占用情况

- **操作：** PowerShell 执行
  `netstat -ano | findstr ":8000 :3000 :5432"`（或分别查），记下每条 `LISTENING` 行的
  本地地址与 PID；有 PID 时用 `tasklist /FI "PID eq <pid>"` 看是什么进程。
- **预期断言：** **只记录即可，不要求清空。** 本安装包的 compose 已支持
  `OPSPILOT_API_HOST_PORT` / `OPSPILOT_WEB_HOST_PORT` / `OPSPILOT_PG_HOST_PORT` 环境变量换端口；
  只要不是干净机，都可能看到别的项目占用（此前 headless 走查就遇到过 `microbubble-agent-app-1` 占 8000）。
- **常见故障与处置：** 若之后首启动报 `Bind for 127.0.0.1:8000 failed: port is already allocated`，
  见下方"常见问题速查"第 2 条；本步不需要预先停掉别的项目。
- **回填格式：** 主脚本 0.3 行写 `8000: 空/被 <进程名> 占用；3000: …；5432: …`。

## 第 1 部分 — 安装（交互式，不用 /S）

### 1.1 [HUMAN] 双击安装包，出现 NSIS 向导

- **操作：** 双击 `OpsPilot-Setup-0.2.0-x64.exe`。
- **预期断言：** 1–3 秒内弹出安装向导窗口（选择安装位置等 NSIS 标准页面），
  窗口标题含 "OpsPilot"。**不是**静默跑完、也不是只闪一个黑框。
- **常见故障与处置：** ① 双击后毫无反应 → 看任务管理器有无该进程；被杀毒拦截时先退出杀软再试并记录；
  ② 弹出的是 SmartScreen 蓝色警告而不是向导 → 这是下一步 1.2 的正常流程，继续；
  ③ 报 "This app can't run on your PC" → 确认下载的是 x64 包、系统为 64 位 Windows。
- **回填格式：** 主脚本 1.1 行写 `向导正常弹出 / 或：无反应 / SmartScreen 先弹出`。

### 1.2 [HUMAN] SmartScreen「已保护你的电脑」提示

- **操作：** 若弹出 SmartScreen，点右下角**「更多信息」**，再点**「仍要运行」**。
- **预期断言：** 点完「仍要运行」后进入正常安装向导。SmartScreen 出现本身**不算问题**——
  安装包未做代码签名（v0.2.0 已知限制），Windows 对所有未签名下载的可执行文件都会提示。
- **常见故障与处置：** ① 找不到「更多信息」→ 把窗口最大化或调整缩放，链接在"不运行"按钮下方；
  ② 企业机器被组策略直接阻断（无"仍要运行"）→ 记录提示原文并停止，联系 IT/项目所有者。
- **回填格式：** 主脚本 1.2 行写 `出现了 SmartScreen，已「更多信息→仍要运行」通过 / 或：未出现 / 被策略阻断（附截图）`。

### 1.3 [H] 完成向导（保持默认）

- **操作：** 沿向导点「下一步」直到「安装」，期间保持默认安装位置；结束时留意"运行 OpsPilot"勾选框。
- **预期断言：** 安装完成，出现完成页，页面带「运行 OpsPilot」勾选框（默认勾选）。
- **常见故障与处置：** 中途报错退出 → 记录报错文案与发生的页面；磁盘不足（需约 6 GB 空闲）→ 清理后重试。
- **回填格式：** 主脚本 1.3 行写 `完成页出现，勾选框存在且默认勾选`。

### 1.4 [HUMAN] 完成安装并首次启动

- **操作：** 保持勾选，点「完成」。
- **预期断言：** OpsPilot 窗口自动打开；桌面上出现 OpsPilot 快捷方式；开始菜单出现 OpsPilot 项。
- **常见故障与处置：** 窗口没自动开 → 手动双击桌面快捷方式，并记录；快捷方式没出现 →
  记录（安装可能仍成功，仅快捷方式创建失败）。
- **回填格式：** 主脚本 1.4 行写 `自动启动：是/否；桌面快捷方式：有/无；开始菜单：有/无`。

### 1.5 [H] 核对安装位置、快捷方式与图标

- **操作：**
  1. 右键桌面快捷方式 → 属性 →「快捷方式」页读"目标"，确认指向
     `%LOCALAPPDATA%\Programs\OpsPilot\` 下的 `OpsPilot.exe`；
  2. 在该目录对 `OpsPilot.exe` 右键 → 属性 → **详细信息**，读"文件版本"与"产品版本"；
     或 PowerShell：`(Get-Item "$env:LOCALAPPDATA\Programs\OpsPilot\OpsPilot.exe").VersionInfo | Format-List FileVersion,ProductVersion`
  3. 看图标本身：应为**蓝方块**样式的应用图标（不是黑圆白三角的默认占位）。
- **预期断言：** 目标路径正确；文件版本/产品版本为 **0.2.0**；图标为蓝方块。
  （headless 走查记录了图标颜色未核对，本项是真人补验点。）
- **常见故障与处置：** 图标显示为白色默认图标 → 记录截图，属于打包资源问题；
  路径不是 `%LOCALAPPDATA%\Programs\OpsPilot` → 记录实际路径（per-user 安装也可能因自定义目录而不同）。
- **回填格式：** 主脚本 1.5 行写 `路径 %LOCALAPPDATA%\Programs\OpsPilot\OpsPilot.exe；版本 0.2.0；图标 蓝方块/异常（截图）`。

## 第 2 部分 — 首次启动与冷启动

### 2.1 [HUMAN] 首启动观察窗口内容

- **操作：** 首次启动后**不要关闭窗口**，观察窗口内容与底部/侧边日志滚动。
- **预期断言：** 窗口显示启动进度或引导文案，日志依次出现类似：
  `Checking Docker` → `Starting postgres, migrate, api, worker` →
  `Backend ready on :8000` → `Dashboard ready on :3210`（行文可能略有差异，顺序一致即可）。
- **常见故障与处置：** ① 直接出现红色错误面板 → 按面板文案处置，最常见是 8000 端口被占
  （见速查第 2 条）与 Docker 未就绪（见速查第 3 条）；② 卡在某一行超过 3 分钟 → 不要关窗口，
  先确认 Docker Desktop 仍在运行，再看下方 2.2。
- **回填格式：** 主脚本 2.1 行写 `看到进度/日志滚动，顺序：____；或错误面板：____`。

### 2.2 [HUMAN] 等待冷启动完成，进入仪表盘

- **操作：** 静置等待，期间可观察窗口日志；**不要中途退出**。首次启动需构建 3 个容器镜像，
  官方口径 5–15 分钟，慢机器/无缓存可能更久。
- **预期断言：** 最终窗口切换到仪表盘页面（顶部导航 Dashboard / Tickets / Runs / Approvals / Knowledge），
  不是错误页。把实际耗时写进记录。
- **常见故障与处置：** ① 超过 15 分钟仍在构建 → 见速查第 4 条；② 窗口显示 compose 失败面板 →
  按面板指引（通常是端口或磁盘），处理后从桌面图标重新启动即可，不用重装。
- **回填格式：** 主脚本 2.2 行"实际记录"写 `耗时 ____ 分钟；进入仪表盘：是/否`。

### 2.3 [HUMAN] 仪表盘可交互

- **操作：** 依次点击左侧/顶部导航：Tickets、Runs、Approvals、Knowledge、Dashboard，来回切两次。
- **预期断言：** 每个页面能正常渲染，无白屏、无报错弹窗；Runs 页此时应为空（"No runs yet"）
  或仅显示本次之前留下的数据。
- **常见故障与处置：** 某页白屏或报错 → 记录页面名与报错文案，继续走完其余页面（不要因单页失败中断）。
- **回填格式：** 主脚本 2.3 行写 `五个页面全部可切换：是/否；异常页面：____`。

## 第 3 部分 — 交互与菜单

### 3.1 [HUMAN] 菜单语言切换

- **操作：** 找到菜单栏的语言入口（英文界面下通常在应用菜单的 View/Language 类菜单，
  中文界面在对应位置），切换 中文 ↔ English，观察整窗变化，再切回。
- **预期断言：** 顶部导航与主要按钮文案随语言整体切换（如 Dashboard→仪表盘）；
  切换即时生效，无需重启。
- **常见故障与处置：** ① 找不到入口 → 记录当前菜单栏内容（这就是有价值的反馈）；
  ② 部分文案没跟着换 → 记下哪几处仍是旧语言；③ 切换后菜单本身不变 → 见速查第 7 条。
- **回填格式：** 主脚本 3.1 行写 `入口位置：____；切换生效：是/否；未跟随的文案：____`。

### 3.2 [HUMAN] 提交一笔测试工单

- **操作：** 进 Tickets 页，按表单填写（参考 README 的示例工单：客户 `CUST-1042`、
  交易 `TX-88219`、金额 `129.00` 之类的字段——以页面表单实际字段为准，随便填也能走），
  点 **Submit ticket**。
- **预期断言：** 出现成功提示面板，并给出一条 run 链接（形如 `/runs/<uuid>`）。
  **立刻把 run id（uuid）抄到主脚本 3.2 的备注里**，后面 3.3–3.5 都要用。
- **常见故障与处置：** 提交后无反应 → 打开浏览器开发者工具（如窗口支持）或看后端健康：
  `curl http://127.0.0.1:8000/ready`，应返回 `{"status":"ready",…}`；仍失败则记录表单内容与现象。
- **回填格式：** 主脚本 3.2 行写 `run id：________；成功面板：有/无`。

### 3.3 [HUMAN] 流程停在「待审批」，出现退款审批卡

- **操作：** 等 run 处理（通常约 10 秒），在 Runs 或 tickets 结果里点开该 run 的详情页。
- **预期断言：** run 状态变为 **Waiting approval**（待审批）；trace 里可见分类/检索/规划调用；
  页面出现一张高风险操作审批卡，内容包含退款金额与交易号（形如
  *"This moves 129.00 out of the account, refunding transaction TX-88219"*）。
  **安全门检查：若 run 不经审批直接变 Completed，属于安全门退化——停止走查并立即报告项目所有者。**
- **常见故障与处置：** ① 超过 1 分钟仍 Pending → 刷新一次页面；仍不动则记录 run id 与当前状态后继续 3.5；
  ② 审批卡里交易号不是 TX-88219 → 说明该工单走了别的分类路径，记录实际内容即可（同样有效）；
  ③ 若因数据残留出现 `invalid_state`（该交易已被退过）→ 见速查第 6 条。
- **回填格式：** 主脚本 3.3 行写 `状态 Waiting approval：是/否；审批卡含 TX-88219 与 129.00：是/否；安全门退化：无/有`。

### 3.4 [HUMAN] 批准一次，重复批准被拒（409）

- **操作：** 在审批卡上点 **Approve**（批准）。等待 run 变更状态。然后（可选但推荐）
  **再点一次 Approve 或刷新后重试**，观察第二次的结果。
- **预期断言：**
  - 第一次：几秒内 run 变 **Completed**，trace 时间线显示退款**执行了一次**；
  - 第二次（重复批准）：被拒绝，前端提示冲突；接口层面为 **HTTP 409**，
    body 含 `"code":"approval_already_decided"`。
- **常见故障与处置：** ① 第一次批准后状态变 Failed 且提到 `invalid_state` → 该交易在历史数据里已被退过，
  属于账本残留（见速查第 6 条），记录后可继续；② 重复批准没被拒而是再次执行 → **严重问题**，
  停止并报告（幂等性失效）；③ 界面上第二次点击无任何提示 → 记录现象（UI 未把 409 显示出来也是反馈）。
- **回填格式：** 主脚本 3.4 行写 `一次批准后 Completed：是/否；重复批准被拒 409：是/否；异常：____`。

### 3.5 [H] 打开该 run 的审计 / trace 页

- **操作：** 在 run 详情页找 trace / audit 区域（或顶部导航 Runs → 该 run）。
- **预期断言：** 能看到完整调用链：分类、知识检索、规划（模型调用）与工具执行记录，
  每条含时间与结果摘要；页面提供**导出**按钮/链接，能导出 JSON。
- **常见故障与处置：** 找不到导出入口 → 记录页面布局；trace 缺少某一环（比如没有检索记录）→ 记录缺失环节。
- **回填格式：** 主脚本 3.5 行写 `trace 完整：是/否；可导出：是/否；缺失环节：____`。

## 第 4 部分 — 退出与重启（数据保留）

### 4.1 [HUMAN] 正常退出应用，核对容器与卷

- **操作：**
  1. 通过应用菜单（或直接关闭窗口）正常退出 OpsPilot；
  2. 退出后 1–2 分钟内，在 PowerShell 执行：
     `docker ps -a --format "table {{.Names}}\t{{.Status}}"` ——
     确认没有仍在运行的 `opspilot-` 容器（postgres / api / worker / web / migrate 应全部
     Exited 或消失）；
     `docker volume ls` —— 应仍能看到 `opspilot_postgres-data` 与 `opspilot_mcp-data`。
- **预期断言：** 应用窗口关闭、进程退出；`opspilot-` 前缀容器停止；**两个数据卷仍在**
  （数据保留的前提）。headless 走查结论一致：容器停、卷保留。
- **常见故障与处置：** ① 容器仍在运行 → 等 30 秒再查一次；仍运行则记录容器名与状态
  （可能是退出钩子未触发，属问题）；② 卷不见了 → **严重**，记录并报告（数据未保留）；
  ③ 想确认迁移容器：`docker ps -a --filter "name=migrate"`，Exited(0) 为正常。
- **回填格式：** 主脚本 4.1 行写 `容器全部停止：是/否；postgres-data 卷在：是/否；mcp-data 卷在：是/否`。

### 4.2 [HUMAN] 再次启动（热启动）

- **操作：** 双击桌面图标重新启动 OpsPilot，掐表记录从双击到仪表盘可交互的时间。
- **预期断言：** 热启动明显快于首启动，约 **1 分钟内**进入仪表盘（镜像已构建、卷已存在，
  只需拉起容器）。
- **常见故障与处置：** 超过 3 分钟 → 记录耗时，检查 Docker Desktop 是否仍在运行；不用重装，
  重启一次应用再看。
- **回填格式：** 主脚本 4.2 行"实际记录"写 `耗时 ____ 秒/分钟`。

### 4.3 [HUMAN] 确认之前的数据还在

- **操作：** 进 Runs（或 Tickets）页，找第 3 部分提交的那笔工单与 run。
- **预期断言：** run 仍在列表里，状态仍为 Completed，trace 可再次打开；审批记录未丢。
- **常见故障与处置：** 数据消失 → 记录 run id 与现象并报告（卷被误删或应用清库都是问题）。
- **回填格式：** 主脚本 4.3 行写 `run ________ 仍在：是/否；状态：____`。

## 第 5 部分 — 主观评价（自由填写）

逐条把答案写在主脚本第 5 部分对应题号下：

1. **安装困惑点：** 例如 SmartScreen 文案看不懂、找不到下一步按钮、进度不透明等；没有就写"无"。
2. **差点做错/做不下去的地方：** 例如不知道要点「更多信息」、冷启动时以为卡死想关窗口。
3. **看不懂的界面文案：** 截图或抄录原文，注明在哪个页面。
4. **总体评分 1–10：** 写整数，并（可选）一句话理由。

## 常见问题速查

| # | 症状 | 原因 | 处置 |
|---|---|---|---|
| 1 | **SmartScreen「已保护你的电脑」** | 安装包未做代码签名（v0.2.0 已知限制），Windows 对未签名下载程序的常规拦截 | 点「更多信息」→「仍要运行」；出现该提示本身不算失败 |
| 2 | **首启动报 `Bind for 127.0.0.1:8000 failed: port is already allocated`**（或 3000/5432 类似） | 本机其他项目占了同名端口 | 记录占用进程；用环境变量换端口后重启应用：在启动前设置 `OPSPILOT_API_HOST_PORT`（如 8100）、`OPSPILOT_WEB_HOST_PORT`（如 3210）、`OPSPILOT_PG_HOST_PORT`（如 5433）。若不想设变量，也可暂停占用端口的那个项目 |
| 3 | **Docker Desktop 未启动 / `docker version` 报错** | daemon 未就绪或 WSL2 问题 | 启动 Docker Desktop 等托盘变绿；WSL 报错按提示更新内核；本步完成前不要开始第 1 部分 |
| 4 | **首启动超过 15 分钟仍在等** | 镜像构建慢、无缓存、网络慢 | 不要关窗口；确认 Docker 在跑、磁盘够（约 6 GB）；可在 Docker Desktop 的 Containers 面板看构建进度；超过 30 分钟记录并报告 |
| 5 | **重复批准返回 409** | 这不是故障：审批已决定，重放被幂等拒绝（`approval_already_decided`） | 这是**预期行为**，把它当作通过依据记录 |
| 6 | **退款报 `invalid_state`（交易已被退过）** | 机器上残留了之前 dev 栈的数据卷，`TX-88219` 已被更早的 run 退过 | 这是账本状态守卫在起作用；若要完整重演金路径，可删除数据卷后重启：`docker compose -p opspilot down` 然后 `docker volume rm opspilot_postgres-data opspilot_mcp-data`（**仅测试数据，删前确认机器上没有别的东西在用这两个卷**），再从 3.1 重来 |
| 7 | **菜单/语言切换点了没反应** | 入口找错、或界面语言跟随逻辑有 bug | 确认点的是语言菜单项而非别的；截图记录点击前后菜单栏与页面文案，作为反馈交回 |
| 8 | **双击安装包无反应或被杀软删除** | 杀软误报或 SmartScreen 静默拦截 | 退出杀软后重试；若仍无反应，记录杀软名称与行为，联系项目所有者 |
| 9 | **窗口显示 compose 失败面板** | 端口占用 / 磁盘不足 / Docker 异常 | 按面板文案处置；处理后从桌面图标重新启动即可，无需重装 |
| 10 | **仪表盘能开但提交工单无反应** | 后端 API 未就绪或请求失败 | `curl http://127.0.0.1:8000/ready` 应返回 `{"status":"ready","checks":{"database":"ok","migrations":"ok"}}`；不通则记录窗口日志最后几行 |

## headless 已验证 vs 只有真人能验证

**headless 已验证（可快速通过，重点看有没有回归）：**
安装包结构与 NSIS 类型、SHA-256 与大小、安装路径与快捷方式存在、
Docker 栈拉起与健康检查（`/ready` 返回 ok）、端口只绑 loopback、
跨源写被拒、金路径（工单→审批→退款执行一次）、重复批准 409、
退出后容器停止、数据卷保留、重启后 run 仍在。

**只有真人能验证（本走查的核心价值，逐项认真做）：**
双击安装的真实体验（1.1–1.4）、SmartScreen 弹窗与绕过（1.2）、
图标观感（1.5，headless 未核对颜色）、首启动窗口进度与日志观感（2.1–2.2）、
页面手动切换流畅度（2.3）、菜单语言切换（3.1，headless 未覆盖）、
表单填写与提交的交互反馈（3.2）、审批卡的可见性与文案（3.3）、
重复批准在 UI 上的提示（3.4 的"第二次点"）、退出按钮/关窗行为（4.1 的第 1 步）、
热启动体感（4.2）、以及第 5 部分的全部主观评价。

## 走查完成后怎么交回

1. **只交主脚本：** 把填好的 [`installer-interactive-walk-2026-11-15.md`](installer-interactive-walk-2026-11-15.md)
   发回给项目所有者。本核对表只是执行辅助，不需要交回。
2. **归档位置：** 项目所有者把结果**追加**进
   [`installer-verification.md`](installer-verification.md)——具体放在文末
   "真人走查记录"位置（现有 headless 记录与其 Deviations 小节之后、不覆盖既有内容），
   新增一个小节，标题写明版本与日期，例如：
   `## Interactive walk-through — v0.2.0, 2026-11-XX, executed by <姓名/代号>`。
3. **记录内容：** 小节内写四块——① 环境与安装包核对结果（大小/SHA-256/版本）；
   ② 第 0–4 部分每步的通过/异常一句话摘要（引用主脚本原表亦可，作为附件）；③
   Deviations：遇到的故障与处置（对照本核对表"常见问题速查"的编号，如
   "hit issue #2, resolved via OPSPILOT_API_HOST_PORT=8100"）；④ 主观评价 4 项与总分。
4. **标注执行者与日期：** 小节标题与开头各写一次执行者（姓名或"未参与构建的同事 A"）
   与日期（YYYY-MM-DD）；若同一人多次执行，按日期倒序追加，旧的记录保持在下方。
5. **异常升级：** 出现"停止并报告"级别的问题（安全门退化、重复退款、数据卷丢失、
   端口绑到 0.0.0.0）时，除写入上述小节外，应**单独第一时间**通知项目所有者，
   不要等走查全部结束。
