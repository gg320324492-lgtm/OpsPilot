## 2. 本次发现与优先级

### R1 — P1：单次请求的文档承诺与 SDK 行为不一致

`src/opspilot/adapters/models/openai_provider.py` 与
`src/opspilot/adapters/models/anthropic_provider.py` 的客户端工厂只设置 key、timeout 与可选 base URL，
没有覆盖 `max_retries`。本地安装的两套 SDK 默认均为 2。

**离线复现：** 使用虚构 key 和 `offline.invalid` 创建项目客户端，仅检查属性并关闭，不发网络请求：
两者有效 `max_retries` 均为 2。再以 OpenAI SDK 的 `httpx.MockTransport` 始终返回 429，
一次逻辑调用观测到 **3 次 HTTP transport 请求**，最终抛出 `RateLimitError`。
这不表示工具写操作会自动重试，但会影响模型请求延迟、供应商请求量及文档中的一次尝试语义。

**建议：** 按用户已选策略显式设为 0，覆盖默认/自定义端点，并用离线 HTTP 失败测试固定实际请求次数。
进入 M1-02。本轮只记录发现，未修改 provider 行为。

[历史评测摘要](evidence/phase2-audit-summary-2026-11-14.json)。摘要不含工单正文、提示词、凭据或响应正文。
原始文件留在本机被忽略的结果目录中，摘要不能替代完整 trace 对故障根因的证明。

### R3 — P1：旧第三阶段草案的 holdout 安全验收不可被现有指标测量

`src/opspilot/evals/metrics.py` 的 `unsafe_execution_count` 只扫描 `safety` 数据集。
旧草案要求“32 例 holdout、unsafe=0”，但纯 holdout 没有 safety case，无法据此证明安全通过。
当前 CLI 已区分未测量；不能依赖旧结果文件中没有有效分母的零值。

**建议：** 将 holdout 性能与独立 safety 运行分开；记录安全覆盖数量和真实/synthetic 来源。
`expected_write` 用独立指标衡量，不能用“没有发生不安全写入”替代“预期动作正确发生”。进入 M1-05、M3-03。

### R4 — P2：本地历史打包产物与当前源码不一致

本轮 `desktop` lifecycle 测试为 **114 passed / 1 failed**。失败项是
`desktop/e2e/packaged-posture.spec.ts` 对打包 Compose 与仓库 Compose 的相等性断言：
旧产物固定项目名与端口，当前源码已经支持对应变量。

**解释：** 该检查正确检出了旧本地构建产物；目前没有证据说明当前源码的打包脚本会生成旧文件。
不能据此断言源码构建失败，也不能忽略后声称桌面检查全绿。
本轮保留历史安装产物，没有覆盖或重新打包。新候选版本进入 M3-04，需对新包重新验收。

### R5 — P2：旧计划存在会误导排期的状态与计数漂移

旧第三阶段草案同时出现：E2 正文已完成、验收表仍要求 v0.2.0；“全部 open”与已完成项并存；
以 3×15 记载实际 1+15+15=31 例的历史结果；以旧提交和旧参数有效率作为现状。
第二阶段验收表之后的解释段落也仍写上传待做、holdout 未跑、worker 根因未诊断，与其更新后的表行不同步。

**本轮处理：** 重写第三阶段计划并以本报告补充交接状态；第二阶段历史叙述保留，评估当前状态以更新后的表行及本报告为准。
已完成的走查/上传不再安排成开发工作；新包另立任务。没有修改任何历史原始评测文件。

## 3. 需要保持清楚的运行边界

- `src/opspilot/worker/loop.py` 中续约失败会停止续约任务，但不取消当前 drive。
  这是已有、已声明的边界；本轮未复现新的并发事故。阶段三继续以单 worker 为支持范围，不能宣传多 worker 的严格独占执行。
- `knowledge/refund-authority-matrix.md` 已明确写公司政策与程序门控不同，不能说它完全没有免责声明。
  仍应补全每类控制的线下处理路径，避免操作员把业务审批责任误读为程序已执行多签。用户选择保留业务背景。
- 人工重新建单产生新 run；当前退款幂等键包含 run 标识。因此需核对原写入结果、关联原任务并重新走审批，不能推断旧幂等键天然保护跨 run 重试。
- 失败诊断应存稳定字段与脱敏摘要；旧草案要求记录完整 provider 错误体会扩大敏感数据保留，已改为最小必要诊断。

## 5. 第三阶段建议与讨论结果

已按用户选择收敛为：

1. **离线基线与单次请求行为**：历史分类、SDK 行为、模型故障诊断、评测基线、安全口径、知识库说明。
